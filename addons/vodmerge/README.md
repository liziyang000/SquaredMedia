# 影片去重与采集审核（VodMerge 1.7.0）

已有视频支持全量重复／匹配冲突排查：首轮建立身份索引并记录开始、完成、耗时和进度，后续每周检查新增视频并与旧库比较。在疑似影片对上点击“AI 复核”，可查看当前身份资料的同一影片概率和置信度；点击“人工审核 / 合并”，可选择目标、预览线路与集数、确认资源合并并回滚。影片合并由人工明确确认，来源影片及双方 ID、资料保留，不删除旧视频。

用于 **其他采集脚本／接口 → MacCMS V10** 的独立后台插件。采集脚本先提交资源到暂存队列；按豆瓣 ID、完整名称、别名、英文名及季数主干召回候选，再由 Jev 给出 `same / different / uncertain` 判断。可人工预览后绑定，也可开启严格自动首次绑定。打开自动补集后，同一来源 ID 的后续更新由 Worker 合并到原视频。

两个自动化开关默认关闭。自动首次绑定要求唯一豆瓣 ID、完整身份证据和 Jev 同时通过，模型高分不能越过身份冲突；新建视频及歧义仍需确认。未部署 Worker 时仍可在后台逐条复核、预览和确认。插件不依赖 VodOps，也不改写 MacCMS 核心文件。

## 安装

需要 PHP 7.4+（PDO MySQL、cURL、mbstring）、单主 MySQL 5.7+、完整 MacCMS V10。安装器需要创建六张 InnoDB 插件表；视频主表可为 MyISAM 或 InnoDB。

1. 将安装包解压到站点 `addons/`，最终结构须为 `addons/vodmerge/Vodmerge.php`。插件管理页能识别 `vodmerge`。本包遵循官方目录规范；没有对特定版本的插件市场上传器作兼容承诺，建议使用下方 CLI 安装载荷。
2. 先备份数据库。以站点 PHP 用户进入站点根目录，执行：

   ```bash
   php addons/vodmerge/bin/install.php --apply
   ```

   它创建或复用 `前缀vodmerge_job`、`前缀vodmerge_binding`，新增 `vodmerge_audit_state`、`vodmerge_audit_run`、`vodmerge_audit_key`、`vodmerge_audit_issue` 四张排查表，复制 `application/admin/controller/Vodmerge.php`、`application/api/controller/Vodmerge.php` 和 `application/admin/view_new/vodmerge/index.html`。目标文件已存在且不同则停止，便于先核对升级版本。不会改视频数据、写密钥或安装 Cron。

3. 将 `addons/vodmerge/examples/vodmerge.php.example` 复制为站点 `application/extra/vodmerge.php`，在服务器本地填写 `ingest_secret`：独立生成的至少 32 字节随机密钥，采集脚本使用同一值。已有配置文件时保留原值，不直接覆盖。

   文件仅供站点 PHP 用户读取，不提交 Git、不从聊天或 URL 传递密钥。也可通过 PHP-FPM 和 CLI 均能读取的 `TYPESAFE_API_KEY`、`VODMERGE_INGEST_SECRET` 环境变量配置；环境变量优先。不要直接把示例空值当作配置完成。

4. 使用超级管理员访问 **你的后台入口 `/admin/vodmerge/index.html`**，例如将原视频管理页路径中的 `/admin/vod/index.html` 换成 `/admin/vodmerge/index.html`。点击右上角 **AI 设置**，填写 Jev API Token，点击“测试连接”，通过后点击“保存连接”。可以手工加入后台快捷菜单。
5. 在原生播放器管理中装好资源所用的播放器代码。新建视频的 `type_id` 必须为本站视频分类 ID。
6. 首次用一部已有视频测试，确认线路、集数和目标 ID 后，再把采集脚本的写入目的地切换为插件接口。**同一批数据不要同时向原生入库接口提交，否则原生入口会绕过此插件。**

已有部署不会自动获得本机钥匙串里的 Jev 密钥，生产端须单独配置。

### 后台配置 Jev Token

- 保存后的 Token 写入 `application/extra/vodmerge.php`，立即供后台复核和后续 Worker 使用；不需要改采集脚本。输入框始终为空，不回显原 Token；不输入新值时保留原配置，“断开已保存的连接”单独删除 Token，保留采集签名密钥及其他配置项。
- “测试连接”有输入时测试新 Token，留空时测试当前有效 Token，均不保存配置。只向官方 Jev API 发送虚构测试资料，不访问任务或视频数据，也不执行合并；会产生一次 API 请求。认证失败、限流、上游故障、网络超时和无效响应分别显示安全提示。“已配置”仅代表保存了 Token，连接是否可用须通过测试确认。
- 页面显示配置来源。设置了 `TYPESAFE_API_KEY` 时优先使用环境变量，后台禁用修改和清除；须由服务器管理员移除该环境变量后，才能改用后台 Token。PHP-FPM 与 CLI 的环境变量应保持一致，避免后台与 Worker 使用不同凭据。
- 保存需要站点 PHP 用户对 `application/extra/` 有写权限。插件在锁内保留现有配置值，以权限 `0600` 的同目录临时文件原子替换配置，并刷新 PHP OPcache。配置必须为返回数组的普通 PHP 文件，值只能包含数组、标量和 `null`；对象、闭包和资源会拒绝保存并保留原文件。保存会规范化为静态数组，原文件中的注释和动态表达式不保留。

### 规则分级和审核顺序

- **强同片依据**：相同正豆瓣 ID、完整标题或别名、有效年份、分类、真实人员交集及季数／版本资料一致。仍需人工检查实际剪辑和音轨，不能直接自动合并。
- **较多同片依据**：完整标题、有效年份、分类与人员资料支持同片，但外部 ID 或版本资料尚不完整。
- **资料不足**：只有标题或主干命中，缺少足以支持同片的正向资料；空值和“未知导演”等占位值不会作为一致证据。
- **资料冲突**：同片候选存在需要核对的身份分歧；相同豆瓣 ID 却年份或季数不同仍保留为冲突。
- **更像不同作品或季数**：明确不同季或不同 ID 且有年份／季数分歧，单列查看，默认不挤占待审核队列。此级别是规则推断，记录并未删除。

规则等级没有概率百分比。只有点选“AI 复核”并得到有效返回后才展示 Jev 概率，模型失败不会生成假概率。页面同时列出依据、缺项、风险；扫描后身份资料变化或影片不存在时显示过期警告，重新分级原快照不能使旧结论变成当前结论。

本版解码 HTML 实体后再分割英文别名，清理标题不可见格式字符，排除占位标题。现有身份索引不会因此自动重建；本次优化不补扫已截断影片、不补扫旧 ID 的资料变更，也没有增加模糊语义召回。每片最多 50 个候选和新增 ID 的每周范围仍保留，排查结果不能解释为已排除全部重复。

## 已有影片排查

1. 在页面选择“已有影片排查”，点击“开始全库排查”。勾选每周新增排查后，首次成功完成起每隔 7 天开启下一轮。安装后默认尚未启动，须明确启动一次。
2. 后台显示扫描范围、实际检查数量、开始／结束时间和总耗时；耗时包含批次之间的等待。可选择最近 10 次记录，分页查看“疑似重复”和“匹配冲突”影片对，展开匹配依据和资料，通过原生视频编辑页人工核对。
3. 需要进一步比较时，点击某对影片的“AI 复核”。服务器使用后台配置的 Jev Token，仅发送这两条影片当前的身份资料；不读取简介、播放／下载地址或会员资料。成功后保存同一作品、同季、同版本的概率分布、结论、模型、置信度、复核时间和耗时。模型概率及分布置信度不等于本站实测准确率，也不授权合并。
4. 成功判断在相同请求的 10 分钟内可复用，重新复核可强制更新；刷新列表不调用模型。影片资料变化或记录删除后，旧判断标记失效；调用期间资料变化会拒绝保存，须重新复核。失败时显示配置、认证、限流、网络或响应格式提示，保留旧的成功记录，不填入虚构概率。原规则分类与排查时依据继续保留。
5. 排查复用规范化片名、别名、英文名、等价季号、季数主干及豆瓣编号建立持久索引；豆瓣编号和完整标题候选优先。每片最多核对 50 个旧库候选，超过时记录候选过多提示。只读身份资料，不读取播放／下载地址，不逐片调用 Jev；这些标签是规则筛出的疑似结果，不代表 AI 判断或全部重复影片。
6. 首轮固定启动时的视频 ID 上界；期间新增留待下一轮。整轮成功后才推进检查上界，失败批次的结果、索引和进度一起回滚，保留任务供后台重试。仅按正常自增 ID 识别新增；旧视频改名／改资料需重跑全库以刷新索引，显式回填较小 ID 或重置自增值需专项补扫。源表为 MyISAM 时，逐批读取不是一致的全库时间点快照；期间删除的记录不会伪计为已处理。

以站点 PHP 用户启动首轮并开启每周新增排查：

```bash
php addons/vodmerge/bin/audit.php --start --weekly --work
```

另安排每分钟一次的排查 Worker，与原采集合并 Worker 独立运行：

```bash
cd /实际站点根目录
/实际CLI-PHP路径/php addons/vodmerge/bin/audit.php --work --max-chunks=100 --max-seconds=20
```

Worker 默认每批 200 条，数据库只写排查自有表；文件互斥和状态行锁防止重复执行。每次在批次／时间预算内执行，错误停止当前调用，下一分钟续跑。页面关闭后仍可运行，周开关关闭不取消当前任务。`--status` 或不带参数仅读取状态；安装器不自动添加此 Cron。检查记录长期保留，界面显示最近 10 次。

## 已有影片人工审核与资源合并

1. 在“已有影片排查”结果卡点击 **人工审核 / 合并**，选择两个影片 ID 中要保留的目标。此操作将另一条影片的资源补充到目标；来源影片仍保留，不删除、不隐藏、不移动评论收藏，也不修改双方资料和访问设置。
2. 核对当前资料是否属于同一作品、同一季、同一版本，勾选人工确认，再点击 **预览线路与集数**。AI 概率只供参考。年份、分类、豆瓣编号、季数或版本硬冲突、影片锁定、访问、审核状态或付费设置不同都会阻止合并，应先通过视频管理核实资料。预览只写插件快照，显示每条线路集数前后和新增线路／集数，不显示播放地址。
3. 明确核对保留目标、来源 ID 和变化后，点击 **确认合并资源** 并确认对话框。预览有效 10 分钟；目标、线路选项变化、关闭面板、翻页或请求失败都须重新预览。确认前重查来源和目标快照、播放器、绑定及未完成写入，只更新目标四个播放字段和更新时间。重复确认不会重复追加。
4. 相同播放器代码不代表相同资源来源，首次合并保守追加独立线路；完全相同且无其他来源占用的线路可复用。已有来源线路同集地址变化时，可审核后勾选 **同集资源不同，追加独立线路**。来源已有多条同播放器线路时按来源槽位分别追踪，不丢线路。此模式只用于已有影片，外部采集输入仍执行原来的严格校验。
5. 合并成功后，卡内显示审核记录及 **回滚本次合并**。回滚恢复目标的合并前播放字段和更新时间；目标后续已修改或其他来源依赖被改线路时停止回滚。回滚后可明确选择目标重新生成新的预览，旧确认凭据不能复用。
6. 写入或回滚响应不确定时，先 **刷新核验**（只读）；对 `applying / rolling_back` 状态使用 **核验并恢复**。恢复按实际前后快照核对，不能匹配时停止，避免重复追加或覆盖外部修改。MyISAM 主表不具备整轮事务回滚保证，因此复用原有持久写入意图、条件更新和恢复记录。

人工合并使用插件保留的内部来源标识 `vodmerge-library`，外部接口不能提交该来源，也不能在采集列表重新排队或由 Worker 执行。预览与合并不用调用 Jev；AI 复核仍由单独按钮按需触发。

## 接入采集脚本

请求：`POST https://你的域名/api.php/vodmerge/submit`。若站点修改过 API 入口文件名，使用实际入口。

```json
{
  "source": "provider-a",
  "source_id": "12345",
  "video": {
    "vod_name": "示例剧 第一季",
    "vod_year": "2026",
    "type_id": 2,
    "vod_douban_id": 0,
    "vod_play_from": "examplem3u8",
    "vod_play_url": "第01集$https://media.example.com/1.m3u8#第02集$https://media.example.com/2.m3u8",
    "vod_play_server": "no",
    "vod_play_note": ""
  }
}
```

`source` 是固定的资源库标识（小写字母、数字、点、横线、下划线，最长 64），不是播放器名称。`source_id` 是该资源库的原始视频 ID（最长 128 字符）；不使用每次采集重新生成的编号。集名与完整地址之间用 `$`，集之间用 `#`，播放组之间用 `$$$`；四个播放字段保持对齐。保留 URL 签名参数，不自行删除 query。

MacCMS 会把原始 `$` 和 `#` 当作播放格式分隔符。上游须提供已正确 URL 编码的地址，插件不会擅自修改签名地址；集名不得包含 HTML、引号或控制字符。海报地址最多 255 字符，以匹配原生短字段。

请求头：

- `Content-Type: application/json`
- `X-Vodmerge-Time`：当前 Unix 秒数，服务器允许前后 300 秒。
- `X-Vodmerge-Signature`：`HMAC-SHA256(ingest_secret, timestamp + "\n" + 原始请求体字节)` 的小写十六进制。

可以直接使用随包附带的 Python 客户端。先在运行脚本的环境中配置 `VODMERGE_INGEST_SECRET`，再执行：

```bash
python3 addons/vodmerge/bin/submit.py \
  --url 'https://你的域名/api.php/vodmerge/submit' \
  --source provider-a \
  --source-id 12345 \
  --file /你的采集结果/one-video.json
```

文件内容是单个 `video` 对象，参考 `examples/video.json`，请替换其中示例播放器与地址。客户端使用 HTTPS，拒绝重定向，不输出密钥。

首次提交返回 HTTP 202 和 `job_id`；相同来源、ID、规范化资源内容重试返回同一任务和当前状态（HTTP 200）。**接收成功只代表暂存成功**，只有 `status=applied` 才表示写入完成。重试已忽略／已回滚版本不会重新执行。单条请求最多 2 MiB；每条资源最多 64 组，每组最多 5000 集；现有 MacCMS 播放组短字段仍受 255 字符限制。

支持字段见 `service/Payload.php::TEXT_FIELDS`，另支持 `type_id`、`vod_douban_id` 和四个 `vod_play_*` 字段。会员权限、付费、计数、播放密码、状态、下载组、剧情分集等输入不会被导入。下载资源仍走原站点独立流程。已有视频合并只更新播放字段和更新时间；资料保持原样。

## 后台操作与自动匹配

1. 点击任务“开始审核”，再点击“比较已有影片”（AI 未配置时为“查找已有影片”，可继续人工审核）。先保留精确豆瓣 ID，再补完整名称、别名、英文名和季数主干，同级优先年份一致；最多展示 10 条。完整标题最多 8 个，主片名和英文名优先，另保留最多 8 个季数主干；单字片名仅做精确查询，避免宽泛召回。硬身份冲突不发送给 Jev；返回后相同作品优先展示，同时说明未通过自动规则的原因。异名片仍可能检索不到，无候选不等于一定是新片。
2. 核对作品、季数、年份、主创和版本，点击候选“选为合并目标”，再点击“预览合并结果”。结果显示目标片名、新增线路和集数，核对后点击“确认执行合并”。预览 10 分钟内有效，确认时重新检查原值。更换目标、线路选项或操作失败后须重新预览。
3. 确认为新作品时，使用“作为新影片预览”，核对后点击“确认新建待审核影片”。新影片先进入原生后台待审核列表，上架前可补充资料、访问权限与静态页。
4. 在插件管理页分别配置“严格自动首次绑定”和“已确认来源自动补集”，并安排 Worker。两个开关独立，均默认关闭。已在审核队列中的普通任务可点击“重新排队”，让 Worker 按当前开关重新处理；已执行、已回滚和不确定新增不会因此重试。

相同任务、相同模型请求的成功判断可在原调用后 10 分钟内复用，页面会标明；复用不会延长有效期。候选 ID、发送的资料或请求内容改变，以及过期、失败或无效结果都会重新调用。“更多操作”内的“重新进行 AI 比较”跳过复用；“重新排队”清除原复核结果。每次复核仍重新查询候选、检查身份冲突、重复 ID 与截断情况，预览和写入前的校验继续执行。

首屏以采集任务为主，AI 设置在弹窗中管理。搜索和状态筛选仅作用于当前最多 30 条任务，翻页可查看更早任务。空列表、读取中、读取失败和筛选无结果分别提示；未收到任务时可展开采集接入说明。已完成任务以记录展示，按钮按服务端任务能力启用，操作期间锁定目标与线路选项；未完成写入会提供核验恢复入口。

页面显示英文名、“同一作品概率”和原置信度，便于人工比较；这些模型数值不代表实测准确率。候选查询只读取身份与模型所需资料，不读取播放／下载地址，减少数据库返回数据量。

别名中段使用 `LIKE '%词%'` 召回，可能扫描别名列；返回上限不能保证扫描量小。大库需实测查询耗时。本版没有新增全文索引或向量库，也不承诺模糊检索覆盖全部异名作品。

### 严格自动首次绑定的条件

只有全部满足时，开启的 Worker 才能合并到已有视频：

- 正向豆瓣 ID 在**整个视频表**中恰好对应一个目标，且双方有效四位年份、本地分类一致。
- 至少一个完整片名／别名一致；只归一化空白、标点和等价季数写法，如 `第一季 / 第1季 / Season 1 / S01`，不把仅主干相同当作正证据。仅有“第一季／Season 1／S01”等季数的别名不能证明作品相同。`vod_en` 只用于召回。
- 有至少一位明确演员或导演相同；“未知／不详／待定”等占位文本不算证据。
- 季数证据一致且无内部矛盾；一侧有季数、另一侧缺失则审核。版本字段须两侧都空或相同，单侧缺失不自动推断。
- Jev 对唯一候选判 `same`，该选项概率至少 `0.98`、分布置信度至少 `0.95`；其他无硬冲突候选须明确为 `different`，概率至少 `0.95`。候选被截断、模型失败或仍有歧义都转人工。
- 预览和写入前重新检查候选集合、身份资料、ID 唯一性、视频锁及未完成写入；仍使用原值条件更新与恢复快照。

这些数值是默认保守门槛，**不是“98% 实际准确率”保证**。先用本站已标注数据验证再开启。示例请求的豆瓣 ID 为 `0`，因此会先进入人工绑定。所有自动处理均保留原视频 ID 和资料；无候选不会自动新建。

推荐在面板计划任务中以 **站点 PHP 用户** 每分钟执行一次：

```bash
cd /实际站点根目录
/实际CLI-PHP路径/php addons/vodmerge/bin/worker.php --limit=1
```

如果调度器用 root 执行，使用 `runuser -u 站点用户 -- ...` 切换，避免产生 PHP 用户无法访问的 runtime 文件。Worker 自带文件互斥，同一站点的写操作另有 MySQL 连接锁。每次最多处理 1～10 个任务；默认 1 个，单次 Jev 超时为 30 秒。活动时输出任务 ID 与状态，空闲时无输出。启动后关闭后台页面，确认下一分钟任务状态仍会变化。

自动补集仅接受来源和目标身份未变、来源线路指纹未变的已确认绑定，包括通过严格自动首绑建立的映射。别名中的季数变化也会暂停自动补集。对于 `failed / unavailable / invalid` 结果，任务保留人工审核，不会因模型失败而自动新增。

不同来源恰好使用相同播放器代码时仍追加独立播放组；只有未被其他来源绑定的相同完整播放组可复用，避免两个来源补集时互相改动线路指纹。绑定后的来源更新只补集，不移除旧集、不改变原有集数顺序。同 URL 的不同数字集名不会重复追加；同集不同 URL（包括签名刷新）进入待确认，可审核后勾选“追加独立线路”保留新旧两组。

## 恢复与回滚

视频主表可能是 MyISAM，因此插件在修改前先持久化 `plan_json` 中的原值和计划值，并使用带原值条件的 UPDATE；不把事务当成全表回滚保证。快照含播放地址，应像数据库备份一样限制访问并纳入数据库备份。

同一目标视频存在未完成写入时，其他来源暂不能预览、写入或回滚，须先恢复该任务。回滚还会检查其他来源的线路依赖，保护 1.0 可能留下的共享映射。

- `applying`：点击“核验并恢复任务”。若主表已与计划值一致，只补齐来源映射和状态；若仍是原值，执行一次条件更新；两者都不一致则停止。
- `creating` 且已有目标 ID：使用核验恢复。若插入结果尚未记录 ID，禁止再次新建；先在原生后台核对是否插入，找到记录后填 ID、预览并确认绑定。若确认插入从未发生，交管理员根据 `creation_json` 处理；插件不会猜测重试。
- “撤销本次合并”：仅恢复已有视频的合并，并且目标值和来源仍符合合并后快照。后续人工修改或更新会阻止回滚。新建视频不自动删除，避免破坏评论、收藏等关联。
- `rolled_back / rejected`：保留审计与幂等记录。卸载插件不会删表或视频。

应用缓存会在写入后清理；CDN、静态 HTML、独立搜索引擎及站外缓存仍按站点现有流程刷新。不要在后台安装或本地测试通过后直接认为生产播放链路已验收。

## 验证与打包

在源码仓库根目录执行：

```bash
npm run test:vodmerge
npm run package:vodmerge
```

输出 `dist/vodmerge-1.7.0.zip` 与 SHA-256 文件。此命令仅生成 VodMerge 归档，不清空其他 dist 文件。现有 `npm run deploy` 和 `npm run deploy:vodops` 不会部署本插件。

仓库内 `tests/fixtures/vodmerge-jev-cases.json` 保存虚构匹配样本；`php scripts/evaluate-vodmerge-jev.php --request` 生成不含预期答案的 API 请求，`--response response.json` 校验真实返回并分别报告模型分类与规则放行结果。脚本自身不读取密钥、不发网络请求。最新验证结果见 [VALIDATION.md](VALIDATION.md)。

自动测试使用真实 SQLite 持久化验证队列、预览、绑定、条件更新、恢复和回滚，并覆盖播放器解析、签名和 Jev 返回协议；SQLite 测试不证明 MySQL `GET_LOCK`、线上权限或 MacCMS 路由运行正常。上线前还须验证一个签名提交、连续两次后台操作、一次首次确认、一次关闭页面后的自动补集、原视频播放及失败恢复。

接口依据：[MacCMS 插件目录](https://www.maccms.la/plugin/plugin-dir)、[TypeSafe HTTP API](https://docs.typesafe.ai/api)、[Choice 判断](https://docs.typesafe.ai/primitives/choice)。Jev 只接收必要元数据，不接收播放 URL、来源接口密钥或会员数据。
