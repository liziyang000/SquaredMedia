3. 对同一任务连续复核两次，第二次应显示复用；强制重新调用应获得新结果。修改候选资料／ID 后再次复核，应重新调用。确认新增冲突、重复 ID 或超过 10 条候选仍阻止自动合并。
4. 在生产等规模测试库分别记录候选查询和模型调用耗时，区分首次复核与缓存命中，不以本地返回字节数替代耗时。
5. 重新生成旧待执行预览，在测试库完成首次确认、关闭页面后的补集、失败恢复及真实播放验收，再恢复正式 Worker。

3. 在测试库开启严格自动首次绑定，以唯一豆瓣 ID 和完整资料测试首次自动合并；再测试重复 ID、异季、缺失季数、低置信度及模型不可用，确认保留审核且不新建视频。用本站已标注样本衡量效果后再决定正式开启。
4. 同一来源 ID 再提交新增一集的资源；开启自动补集并关闭页面，确认后台 Worker 执行后只追加一次。1.0 旧绑定须先人工预览确认以更新身份快照。
5. 原样重试该请求，确认复用任务；改变同集地址或目标身份，确认留待审核。普通审核任务可重新排队，已执行／回滚任务不能因此重做。
6. 在测试数据上执行一次条件回滚和未完成写入恢复，并确认应用缓存和站点独立静态页／CDN 更新符合现有流程。
