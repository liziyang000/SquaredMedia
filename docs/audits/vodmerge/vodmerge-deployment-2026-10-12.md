## 真实库候选召回与耗时

从库内读取 131 条影片元数据，导出仅匹配所需字段，不导出播放地址、下载地址、会员资料或密钥。选取 8 个召回案例，包含原始记录及真实别名、清除豆瓣 ID、等价季号和标点等受控输入变换；这些不是独立来源的采集样本，也不是随机抽样。

在生产 MySQL 的只读事务中，通过 Reflection 调用实际 `Service::candidates()`。每版每例执行 3 轮。1.1 从升级前备份载入，1.3 从实际部署目录载入；两个版本独立进程，1.1 先运行、1.3 后运行，没有清空数据库／操作系统缓存或改变线上索引。

计时包括候选生成、SQL execute 和 fetchAll，不包括冲突过滤、Jev、任务写入或整个后台 HTTP 请求。表内显示每例 3 轮中位数；字节指标是服务器内候选行的 JSON 序列化大小，包含可能存在的第 11 条截断探针，不是网络传输量。

每例前 10 条候选命中至少一个预先给定的同作品目标 ID 视为命中。1.1 为 7／8，1.3 为 8／8；不能把它解释为全库匹配准确率。单字片名旧版未发查询，因此旧版的 0.03 ms 不代表成功查询更快。季号案例两版均返回 11 条并触发截断，自动合并继续受覆盖不完整保护。

两版共同成功召回的 7 例，案例中位耗时的中位数由 2,972.68 ms 降至 2,616.59 ms，约减少 12.0%。标点案例略慢，存在顺序运行、热缓存和实时负载影响；这不是吞吐或严格冷缓存基准。对应首轮候选行序列化总量由 127,358 字节降至 27,356 字节，约减少 78.5%；列数从 87 降到 14。

现场 EXPLAIN：豆瓣 ID 精确查询和别名中段 LIKE 均为 `type=ALL`，`key=null`，估计 334,875 行，`Using where; Using filesort`。因此当前主要耗时仍来自全表扫描和排序，减少返回字段未消除这些秒级查询。现有索引包括片名、别名等，但未为本轮增加索引或修改视频表；下一步应单独评估豆瓣 ID 索引及召回查询拆分。

## 原始影片对与模型评估边界

另在看任何 Jev 答案前，依据现有元数据固定 20 对未经修改的真实影片记录：7 对同作品、9 对不同作品、4 对资料不足／冲突。标签是本次独立资料核验目标，未经过用户复核或外部权威片库确认，不能当作全库绝对真值。

本地用与已部署源码一致的 `Payload` 检查这 20 对：9 对不同作品／季数均被硬冲突规则阻止；7 对同作品中，《长津湖》和《釜山行》各一对因库内子分类 ID 不同也被拦截，其余 5 对可进入模型复核。4 对不确定中，2 对因年份冲突被拦截，2 对特别版证据不对称须由模型及人工审核处理。这些结果是确定性规则行为，不是 Jev 分类命中率。

样本发现库记录自身问题：`210624`《沙丘》主创与简介主题错配，`203332`《西游记》主创与简介信息冲突，`347431`《三体2024》标题年份与年份字段不同。原始记录保持原值；这些问题与模型误判分开记录。

实际 Jev 请求按 1.3 原有 `Jev::request()` 协议准备，没有更改提示词，不包含预期标签。首组真实影片元数据调用在执行前被自动审批拒绝，理由是缺少该批资料发送至 Jev/TypeSafe 的明确授权；没有 API 返回，不能记录模型准确率、调用耗时或缓存命中耗时。此前其他任务的 HTTP 451 不作为本次真实模型调用结果。

继续模型实测需完成两个独立事项：明确授权将本批最多 20 对必要影片元数据发送到 `https://api.typesafe.ai/v1/systemone`；配置服务器 Jev Token，或明确授权将本机 `codex-typesafe-api-key` 写入此服务器的 VodMerge 配置。当前服务器 Token 状态为未配置。本机钥匙串仅检查就绪状态，未打印或传输密钥。

逐轮耗时、候选 ID、预期标签及规则原因见 [结构化记录](vodmerge-real-matching-2026-10-12.json)。原始元数据与可执行测试脚本留在私有临时／备份目录，不加入安装包。

## 回退

如需回退，先暂停 `/etc/cron.d/vodmerge-squaredmedia` 并取得原 Worker 锁，保留锁 inode。用私有备份中的 `addon-before-switch` 或 `addon` 恢复旧插件，恢复 `application/admin/controller/Vodmerge.php`、`application/api/controller/Vodmerge.php`、`application/admin/view_new/vodmerge/index.html`，核对所有者／权限并刷新 PHP-FPM 后恢复原 Cron。保留现有密钥文件、数据库和审计，不用本次备份覆盖整个数据库。
