## 推荐阅读顺序

1. 先读“当前项目深度总览”，建立稳定的模块、运行时和证据边界。
2. 需要继续当前分支时，再读最新带日期工作区快照，并现场刷新 Git 状态。
3. 只有涉及商业模式或长期架构时，才进入商用视频网站行业参考。
4. 开发前回到对应顶层模块文档，把建议拆成范围明确的设计、接口、测试和验收文档。

## 维护约定

- 通用行业参考、当前项目事实、未提交工作区和生产运行证据必须分开描述。
- 外部来源优先使用平台、标准组织和监管机构的官方页面。
- 法律、牌照、税务、应用商店和平台规则可能变化，正式上线前必须重新核验。
- 知识库中的建议指标是工程起点，不自动成为生产 SLO。
- 项目实现变化应先更新对应模块文档；跨模块架构或能力边界变化时再同步当前项目总览，外部研究变化时更新参考专题。
- 易变的 Git/部署状态使用新的带日期 note 保存，不覆盖旧快照。
