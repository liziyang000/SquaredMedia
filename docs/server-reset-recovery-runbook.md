### R-003：处理服务器重装后的 SSH 主机密钥变化

- 状态：SSH 登录已恢复（操作人说明），指纹核对证据待补
- 时间：2026-08-01（具体时间未记录）
- 目的：恢复原电脑到重装后服务器的 SSH 连接，同时保留主机身份校验。
- 现象：执行 `ssh root@144.34.184.95` 时出现 `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!` 和 `Host key verification failed`。
- 截图证据：
  - 远端本次提供的是 ED25519 主机密钥。
  - 显示的指纹为 `SHA256:LOmyo1OCJG7sMjaqdH4qu46LEODL0FYyKIhT9lYkxIU`。
  - 本机冲突项是 `/Users/bytedance/.ssh/known_hosts` 第 4 行中的旧 ECDSA 密钥。
  - 本机已经生成 `/Users/bytedance/.ssh/known_hosts.old`，但当前 IP 的旧记录仍然造成冲突。
- 原因：服务器重装会重新生成 SSH 主机密钥；原电脑仍缓存重装前的主机密钥，因此 OpenSSH 的严格校验按中间人攻击风险阻止连接。这不是 SSH 账号或密码错误。
- 安全验证：先通过搬瓦工控制台进入新服务器，执行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`；输出必须与上面的 ED25519 指纹完全一致。
- 建议处理：确认指纹一致后，在原电脑执行 `ssh-keygen -R 144.34.184.95`，再执行 `ssh root@144.34.184.95` 并核对、接受新指纹。
- 实际结果：操作人说明已经完成 SSH 登录；实际执行的旧密钥移除命令和指纹核对结果尚未补充。
- 非默认端口：如果 SSH 使用非 22 端口，还需按实际端口检查或移除 `[144.34.184.95]:端口` 对应记录。
- 禁止做法：未核对指纹前不要接受新密钥，也不要通过关闭 `StrictHostKeyChecking` 绕过校验。
- 异常与处理：如果控制台读取的指纹与截图不一致，立即停止连接并检查 IP、服务器实例和网络路径。
- 回滚方式：需要恢复本机旧记录时，可从 `/Users/bytedance/.ssh/known_hosts.old` 取回；不要覆盖其中其他主机记录。
