# MacCMS 搜索优化补丁

MacCMS 核心由服务器独立维护，不在主题仓库中。`search-optimization.patch`
只修改两个核心模型，不能用主题全量发布替代本补丁：

- `VodSearch.php`：ID 缓存未命中后取得文件锁，重新读取缓存再决定是否扫描。
  使用运行目录下最多 256 个锁文件，不删除活动锁文件；单机 PHP 进程退出会释放锁。
- `Vod.php`：仅 `pageurl=vod/search` 且未指定字段时裁剪列表字段；保留简介原文、
  URL 帮助函数、分类和用户组所需字段。非默认字段进入独立列表缓存键，默认完整字段的其他页面保留原键。

不修改搜索间隔、WAF、权限筛选、匹配规则、分页、详情/播放查询、缓存有效期或数据库结构。
单个全新词仍需执行原来的包含匹配；本补丁减少同词并发重复扫描和搜索结果载荷。

基线文件 SHA-256：

```text
VodSearch.php 94c31f07a9522975a72b5ddb0610621f4ea7cf91266a81186d48f50bd0e58cc1
Vod.php       afd47e7703b7b3a440f6388d0518bb2091a29036eff6ca1a3824de82243ce894
```

发布时先备份两个模型，使用部署现场文件应用补丁并检查 PHP 语法、所有者及运行目录可写性。
先在副本中执行 `patch --dry-run -p1`，有漂移时检查差异，禁止强行覆盖核心。
预先验证完成后逐文件原子替换；失败时原子恢复备份。无需清空 Redis 或模板缓存、无需重启服务。
部署时预置这 256 个空锁文件并设为 PHP-FPM 用户所有，避免不同 CLI 用户先创建文件造成权限冲突。
文件名仅使用关键词与字段摘要的前两位，不包含搜索词；不要删除或替换活动锁文件。
调用真实模型的 CLI 验收或任务须使用相同的 PHP-FPM 用户运行；不要以 root 创建运行期锁文件。

补丁应用后的并发回归测试（使用独立临时目录和模拟数据库，不访问生产数据库）：

```bash
php tests/search-cache.test.php /path/to/patched/VodSearch.php
# 或通过 npm 传入同一个已应用补丁的模型路径
npm run test:search-cache -- /path/to/patched/VodSearch.php
```

该测试需要仓库外的核心模型，不加入默认 `npm test`；常规主题发布也不应用本补丁。

测试覆盖四进程同词首次扫描一次、重复命中、空结果、字段键隔离、多词合并与查询异常。
线上验收另测首次/重复搜索、结果与详情链接一致性、筛选与翻页、登录态、收藏和实际播放。
只重置本轮明确确认原本不存在且由验收创建的关键词缓存，禁止全局清缓存。
