### 4. 2026-07-27 10:04

- **用户请求**：react模版登录提示CSRF Token 无效是什么原因、

- **结果**：原因已确认：这是首次加载时的 PHP Session 竞态，不是账号、密码或验证码错误。 - React 登录页会同时请求 `navigation` 和 `session`：[AppShell.tsx](apps/web/src/app/AppShell.tsx:15)、[AccountContext.tsx](apps/web/src/app/AccountContext.tsx:104)。 - 新浏览器还没有 `PHPSESSID`，两个请求会分别创建不同 Session，并各自写入 Cookie。 - React 保存的是 `session` 返回的 CSRF Token，但最终 Cookie 有时被 `navigation` 响应覆盖。 - 登录请求随后携带旧 Session 的 Token：[account.ts](apps/web/src/api/account.ts:341)。 - 后端在验证账号前先比较 Token：[ApiRequest.php](addons/pingfangapi/service/ApiRequest.php:106)、[ApiRequest.php](addons/pingfangapi/service/ApiRequest.php:514)，不匹配便返回 `CSRF Token 无效`。 线上实测： - 干净浏览器也能复现。 - 登录请求 Token 与当前 PHP Session Token 都是 64 位，但内容不相等。 - 6 次全新浏览器采样中，有 2 次最终 Cookie 被 `navigation` 会话覆盖。 - 将 `session → 验证码 → login` 串行请求时，CSRF 正常通过并进入验证码校验，说明后端机制正常。 刷新页面可能偶尔恢复，但不可靠。正确修复是让 `session` 初始化完成后再请求 `navigation`；同时可以在精确遇到 CSRF 403 时刷新 Session 并最多重试一次。当前只完成诊断，尚未修改代码。
- **轮次状态**：completed
