- **结果**：结论：这是 MacCMS“假墙防御 → 编码方式”的 Unicode 字节序 Bug，不是字体、浏览器、数据库或主题 CSS 导致的。 线上配置为 `wall_filter=1`，搜索词会经过 `mac_unicode_encode()`。该函数使用未指定字节序的 `UCS-2`，在当前 Linux/PHP 环境中把“中”的 `0x4E2D` 倒置成 `0x2D4E`，最终输出： ```text 错误：&#11598;&#64854;&#27473;&#10073;&#56451; 正确：&#20013;&#22269;&#20843;&#22823;&#33756; ``` 官方 MacCMS 当前源码也存在这段实现：[mac_unicode_encode / mac_escape_param](https://raw.githubusercontent.com/magicblack/maccms10/refs/heads/master/application/common.php)。 推荐先采用最简单的修复： 1. 进入 MacCMS 后台“系统设置/网站参数”。 2. 找到“假墙防御”。 3. 从“编码方式”改为“关闭”。 4. 保存并清理 MacCMS 缓存，再重新搜索。 关闭它不会关闭基础 XSS 转义，`wd` 仍会经过 `htmlspecialchars()`：[MacCMS 参数处理源码](https://raw.githubusercontent.com/magicblack/maccms10/refs/heads/master/application/common.php)。 如果必须保留“假墙防御”，则修改线上 `application/common.php`： ```php // 原代码 $str = iconv($encoding, 'UCS-2', $str); // 修改为 $str = iconv($encoding, 'UCS-2BE', $str); ``` 同时把解码函数改为： ```php // 原代码 return iconv('UCS-2', $encoding, $unistr); // 修改为 return iconv('UCS-2BE', $encoding, $unistr); ``` 主题文件只是直接显示 `$param.wd`，例如 [search.html](template/pingfangvideo/html/vod/search.html:4) 和 [head.html](template/pingfangvideo/html/public/head.html:29)，不需要修改。 本轮只做了线上只读检查，没有改动本地或服务器文件。
