### 1. 2026-08-10 18:31

- **用户请求**：当前存在问题，用户在新设备登录后播放记录为空，这是什么原因

- **结果**：结论：不是新设备登录后把历史删除了，而是当前“播放记录”存在两套数据源，而且线上还有域名静态资源故障。 - `/label/history` 是本地记录页，明确读取 `localStorage`。换设备后本地存储为空，登录也不会同步旧设备数据：[history.html](template/pingfangvideo/html/label/history.html:8)、[app.js](template/pingfangvideo/js/app.js:3103)。 - `/user/plays` 才是账号记录页，读取服务端 Ulog：[plays.html](template/pingfangvideo/html/user/plays.html:22)。播放页虽然放置了 `mac_ulog_set type=4` 标记：[play.html](template/pingfangvideo/html/vod/play.html:41)，但写入依赖 MacCMS 的 `home.js` 和 `/user/ajax_ulog` 接口。[官方说明](https://www.maccms.la/theme/writing-a-theme) - 本地时间轴还有实现错误：线上 MacCMS `home.js` 把 `mac_history` 写入 Cookie，当前主题却从 `localStorage` 读取，并且期待数组格式，存储位置和数据结构都不一致。 - 2026-08-10 18:33 的线上检查显示，[非 www 的 home.js](https://ping2video.xyz/static/js/home.js) 返回 404，而 [www 的 home.js](https://www.ping2video.xyz/static/js/home.js) 返回 200。新设备如果访问非 www 域名，核心脚本无法运行，账号播放记录也不会写入。 因此根因是“本地记录未跨设备同步 + 非 www 静态资源路由异常”，不是设备管理插件主动清空了历史。若地址栏是 `/label/history.html`，为空属于当前设计/实现问题；若是 `/user/plays.html`，则说明此前 Ulog 没有成功写入账号。需要修改，单纯重新登录或刷新不能根治。本次仅排查，未改代码或生产数据。

### 4. 2026-08-10 18:49

- **用户请求**：播放记录在那个数据库表中，我去看下

- **结果**：播放记录在： ```sql mac_ulog ``` 其中： - `ulog_type = 4`：播放记录 - `ulog_mid = 1`：视频 - `user_id`：账号 ID - `ulog_rid`：影片 `vod_id` - `ulog_sid`：播放线路 - `ulog_nid`：集数 - `ulog_time`：最后播放时间 只读查询某个账号： ```sql SELECT ulog_id, user_id, ulog_rid, ulog_sid, ulog_nid, FROM_UNIXTIME(ulog_time) AS played_at FROM mac_ulog WHERE user_id = 你的用户ID AND ulog_mid = 1 AND ulog_type = 4 ORDER BY ulog_time DESC; ``` 先不要执行 `DELETE` 或 `UPDATE`。如果站点修改过数据库前缀，实际表名是“自定义前缀 + `ulog`”。
