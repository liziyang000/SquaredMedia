# SquaredMedia 项目管理

这里是当前 Obsidian Vault 的项目管理区。项目、里程碑和任务都保存为 Markdown 文件，三个 `.base` 文件只负责聚合、计算和展示。

## 管理模型

| 层级 | 负责回答 | 关联方式 |
| --- | --- | --- |
| 项目 | 为什么做、最终目标是什么 | 一个项目包含多个里程碑和任务 |
| 里程碑 | 什么阶段性结果必须达成 | `project` 链接所属项目 |
| 任务 | 下一步具体做什么 | `project` 链接项目，`milestone` 可选链接里程碑 |

项目笔记会自动显示所有链接到自己的任务和里程碑，无需为每个项目单独维护列表。

## 开始使用

1. 在 **设置 → 核心插件 → 模板** 中，将模板文件夹设为 `项目管理/模板`。
2. 在对应目录新建以事项名称命名的笔记，并插入相应模板。
3. 新建里程碑时，将 `project` 设为项目内部链接，例如 `"[[项目管理/项目/SquaredMedia]]"`。
4. 新建任务时填写 `project`；如果任务服务于某个里程碑，再填写 `milestone`。
5. 日常打开 [[仪表盘]]；先处理“行动焦点”，再检查近期计划和待整理事项。

> [!tip]
> 在 Bases 表格中直接编辑单元格，会同步修改对应 Markdown 的属性。链接字段也可以直接在属性面板中选择笔记。

## 字段规范

### 公共字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | 文本 | 固定为 `project`、`milestone` 或 `task` |
| `status` | 文本 | 使用下方各层级的固定状态值 |
| `owner` | 文本 | 单一主负责人；多人协作写在正文中 |
| `blocked` | 复选框 | `true` 或 `false` |
| `created` / `updated` | 日期 | 创建日期与最近复盘日期 |

### 项目字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | 文本 | `待启动`、`进行中`、`暂停`、`已完成`、`已取消` |
| `priority` | 文本 | `P0`、`P1`、`P2`、`P3` |
| `area` | 文本 | 所属业务或模块 |
| `start_date` / `target_date` | 日期 | 开始和目标日期 |
| `progress` | 数字 | `0` 到 `100` |
| `next_action` | 文本 | 一条具体、可执行的下一步 |

### 里程碑字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | 文本 | `待启动`、`进行中`、`已完成`、`已取消` |
| `project` | 内部链接 | 必填，指向所属项目 |
| `target_date` / `completed_date` | 日期 | 目标和实际完成日期 |
| `success_criteria` | 文本 | 一句话验收标准 |

### 任务字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | 文本 | `待处理`、`进行中`、`等待`、`已完成`、`已取消` |
| `priority` | 文本 | `P0`、`P1`、`P2`、`P3` |
| `project` | 内部链接 | 所属项目；留空会进入“收件箱” |
| `milestone` | 内部链接 | 可选，指向所属里程碑 |
| `due_date` / `completed_date` | 日期 | 截止和实际完成日期 |

## 维护节奏

- 每天：处理“行动焦点”，为收件箱任务指定项目。
- 每次推进后：更新状态、日期、阻塞信息和 `updated`。
- 每周：检查未来 7 天任务、未来 30 天里程碑、待补信息和所有阻塞事项。
- 项目结束时：确认关联任务和里程碑已关闭，再将项目设为 `已完成` 或 `已取消`。

## 当前边界

- 这是原生 Bases 方案，不提供系统通知或自动提醒。
- 项目卡片适合概览；“按状态分组”的表格适合执行，但不是可拖拽的看板界面。
- 日期视图用于计划检查，不会自动写入系统日历。
- Codex 对话档案是 2026-08-10 的同步快照；后续新增任务需要再次同步才会进入项目。
